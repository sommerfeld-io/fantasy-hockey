### bmad-review (Edge-Case Hunter, Verification Gap, Adversarial lenses on the full epic diff)

**Edge-Case Hunter**: no findings — the const rename is a clean no-op, both new tests' call sites match their callees exactly, and the one asymmetric nil-check between the two tests (`err != nil` vs. `err != nil || st == nil`) is a dead path (`openStore`/`store.New` never return a nil store with a nil error).

**Verification Gap** — 1 finding, merged below with Adversarial's #3 (same root cause):

- **`DefaultSeason`'s value has no independent safety net** — exporting the const and updating the two pre-existing `store_test.go` assertions to reference it (rather than a literal) turned those assertions into tautologies ("the value `New()` assigned equals the constant `New()` was given"). No test anywhere validates `DefaultSeason`'s actual value or format independently. **Disposition: fix now.** This matters specifically because Epic 6's whole purpose is season rollover, and `DefaultSeason` is exactly the value a human must remember to bump in Go source before each new season — nothing would catch a forgotten or malformed bump. Neither prior review pass caught this because it's a second-order effect of combining Pass 1's fix (export the const) with Pass 2's fix (close the remaining duplication) — visible only when looking at the diff's cumulative effect, which is precisely what a retrospective is for.

**Adversarial** — 10 findings; consolidated with the item above and grouped by root cause:

1. *(merged into the `DefaultSeason` finding above)* — the epic context and story spec never mention that `DefaultSeason` must be manually bumped before a real new season, or that the current bootstrap mechanism doesn't itself guarantee the *value* is current — only that a value gets written.
2. **No log line when a fresh file is bootstrapped** — the single most operationally consequential moment in this epic (a brand-new, empty pool file being created) produces zero log output. **Disposition: fix now** — add an info-level log line (e.g. `"bootstrapped a new data file" path=... season=...`) in `openStore`'s bootstrap path, directly serving the epic's own "confirm the rollover worked" need. A mistyped rollover path currently fails silently into an empty new pool with no diagnostic trail.
3. **`epic-6-context.md`'s "read-only history" phrasing overstates the actual guarantee** — nothing enforces this at the OS level; it's purely procedural (nobody repoints `DATA_FILE` back at an old file). If an operator ever did, the app would happily resume writing into what was meant to be frozen history, with no guard. **Disposition: fix now** — reword to be precise about what's actually guaranteed (procedural, not enforced).
4. **Doc comment overclaims "end-to-end through main's actual startup path"** for `TestOpenStoreShouldBootstrapAFreshSeasonWhenTheResolvedPathDoesNotExist`, which calls `openStore` directly, never `resolveConfig`/`run()`. In practice this is low-risk — `resolveConfig`'s flag/env precedence logic never touches the filesystem, so it can't behave differently based on path existence — but the comment is still inaccurate. **Disposition: fix now** (cheap: correct the comment's claim to match what's actually exercised).
5. **Archived and fresh files use two separate `t.TempDir()`s instead of one shared directory** — the realistic rollover topology (per the epic context's own example) is both files coexisting in the same directory, which `writeLocked`'s atomic temp-file write never gets exercised against. **Disposition: fix now** (trivial: one shared `t.TempDir()`).
6. **No test for a nonexistent parent directory** in the resolved path (plausible during a hand-typed rollover path). **Disposition: fix now** (add an I/O matrix row + test; also worth checking the resulting error message is operator-legible, not a bare OS error).
7. **Neither new bootstrap test asserts log silence** on a clean bootstrap, unlike the sibling `TestOpenStoreShouldNotWarnForAWellFormedFile` pattern this story otherwise matched closely. **Disposition: fix now** (cheap, matches established convention).
8. **Commit `2930c75` is typed `test(store)` but also renames/exports a production identifier** (`defaultSeason` → `DefaultSeason`) — a public API surface change riding along under a no-release-impact commit type. **Disposition: defer as a process lesson**, not a fix against the existing commit — rewriting already-made local history for a classification nit isn't worth the risk. Lesson: when a small production rename rides along with a test-only commit, type it `refactor` or split it.
9. **`DefaultSeason`'s export has no doc-comment guardrail** against a future package branching on `store.Season() == store.DefaultSeason` to build the kind of cross-season-aware logic the epic explicitly forbids. **Disposition: fix now** (cheap: one GoDoc line warning against that use).
10. **Spec Change Log section stayed empty** even though this diff's Pass 2 edited the spec's Code Map/Implementation Notes — that record went into the Review Triage Log instead of its dedicated section. **Disposition: accept as-is** — the information is captured, just under a different heading than its documented purpose; not worth a dedicated backfill action.

## Behavior verification

Story 6.1's own review passes only tested the bootstrap/rollover mechanism in-process (calling `openStore` directly in Go tests). This retrospective ran it for real:

- Copied the real `fantasy-hockey.yml` to a separate path as a stand-in archived file, recorded its md5sum.
- Built the actual binary and ran it with `DATA_FILE` pointed at a genuinely nonexistent fresh path in the same directory as the "archived" file, with a real `SESSION_SECRET`.
- Confirmed: the fresh file was created with `season: 2026-27` and `players: []` exactly as expected; the archived file's md5sum was byte-identical before and after the run.

This is a stronger confirmation than the unit tests alone provide (real binary, real directory, real coexisting files) and found no discrepancy from what the tests already claimed.

## Action items

Owner: whoever picks up the next season-rollover-adjacent story.
2. **Add a bootstrap log line** — `openStore`'s missing-path branch should log at info level when it creates a fresh file (path + season), so a mistyped rollover path doesn't silently produce an empty pool with no diagnostic trail. Owner: next dev touching `main.go`/`internal/store`.
3. **Correct `epic-6-context.md`'s "read-only history" overstatement** — reword to reflect that this is procedural, not OS-enforced, and note what happens if `DATA_FILE` is ever pointed back at an archived file (it becomes writable current state, by design). Owner: whoever next edits `epic-6-context.md`.
4. **Tighten `main_test.go`'s two new tests**: correct the doc comment overclaiming `resolveConfig`/`run()` coverage; colocate the archived and fresh files in one shared `t.TempDir()` for a realistic same-directory topology; assert log silence on a clean bootstrap, matching the sibling test convention. Owner: next dev touching `main_test.go`.
5. **Add a nonexistent-parent-directory test** for `openStore`/`store.New`, and check the resulting error is operator-legible. Owner: next dev touching `internal/store`.
6. **Add a GoDoc guardrail on `DefaultSeason`** warning against branching on it outside store/test code, to close the door on future cross-season-aware logic the epic explicitly forbids. Owner: next dev touching `internal/store/store.go`.
7. **Process lesson (no code action)**: a commit combining a production rename with test additions should be typed `refactor` or split, not `test` — don't rewrite the existing commit for this, just apply going forward.
