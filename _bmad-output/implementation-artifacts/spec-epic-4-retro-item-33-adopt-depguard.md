## Intent

**Problem:** AD-21 says import-boundary enforcement runs via `golangci-lint`'s `depguard` linter, failing `task go:lint` (AD-5's build gate) on a violation. In reality, `.golangci.yml` has no `depguard` entry - AD-8's dependency-direction rule (`docs/architecture.md`: presentation → domain, domain → infrastructure, with `standings → scoring` the one sanctioned domain-to-domain exception) is enforced only by hand-written Go tests parsing each package's own source with `go/parser`, scattered across `internal/scoring/imports_test.go`, `internal/standings/imports_test.go`, and two tests inside `internal/web` (`leaderboard_test.go`'s `TestWebShouldNotImportScoring`, `compare_test.go`'s `TestCompareShouldNotImportScoringOrStandings`) - a violation only fails `go test`, not the lint gate AD-21 actually promises (epic-4 retrospective, item 33).

**Approach:** Add a `depguard` rule set to `.golangci.yml` encoding the same boundaries the hand-written tests check today: `internal/scoring` may import only `internal/store` (plus stdlib); `internal/standings` may import only `internal/scoring`/`internal/store`; `internal/web` may not import `internal/scoring` directly; `internal/web/compare.go` specifically may not import `internal/scoring` or `internal/standings`. Delete the now-redundant hand-written guard tests (the retro item names three; a fourth, `compare_test.go`'s, was added afterward in epic 5 and is superseded the same way) - keeping any other test/helper in the same files that isn't itself a boundary-violation check (e.g. `TestStandingsShouldImportScoringForEveryPointValue`, a positive "does import" assertion, stays).

</frozen-after-approval>

## Implementation Notes

Added `depguard` to `.golangci.yml`'s enabled linters plus a `settings.depguard.rules` block with four rules, derived by reading the actual depguard v2 source (`$GOPATH/pkg/mod/github.com/!open!pee!dee!p/depguard/v2@v2.2.1`) and golangci-lint's own `DepGuardSettings`/`DepGuardList` config struct, rather than guessing the YAML schema:
- `scoring`: `files: [**/internal/scoring/*.go, !**/internal/scoring/*_test.go]`, `allow: [$gostd, internal/store]` - whitelist mode, matching `TestScoringShouldImportNoInternalPackageButStore`'s exact semantics.
- `standings`: same shape, `allow: [$gostd, internal/scoring, internal/store]` - matching `TestStandingsShouldImportNoInternalPackageButScoringAndStore`.
- `web`: package-wide, `deny: internal/scoring` - matching `TestWebShouldNotImportScoring`.
- `compare`: file-scoped to `**/internal/web/compare.go` only, `deny: [internal/scoring, internal/standings]` - matching `TestCompareShouldNotImportScoringOrStandings`. File-scoping this one specifically (not package-wide) is required: `leaderboard.go` legitimately imports `internal/standings`, so a package-wide ban would break real, needed functionality.

Before deleting anything, checked each non-test file's actual current imports (`grep`) to confirm the new `allow` lists wouldn't break anything real: `scoring`'s non-test files import only `slices`/`strconv`/`internal/store`; `standings`'s import `cmp`/`slices`/`strings`/`internal/scoring`/`internal/store`; `web`'s import `internal/auth`/`internal/clock`/`internal/mailer`/`internal/standings`/`internal/store` (never `internal/scoring` directly); `compare.go` imports only `clock`/`store`.

Deleted the retro item's named three hand-written guard tests plus a fourth, `compare_test.go`'s `TestCompareShouldNotImportScoringOrStandings`, added in epic 5 (after the epic-4 retrospective was written) and superseded by the same `depguard` adoption: `internal/scoring/imports_test.go` (deleted the whole file - nothing else in it), `internal/standings/imports_test.go`'s `TestStandingsShouldImportNoInternalPackageButScoringAndStore` and its now-unused `allowedInternalImports` var (kept `internalPrefix`/`internalImports` and `TestStandingsShouldImportScoringForEveryPointValue`, a positive "does import" assertion, not a boundary guard), `internal/web/leaderboard_test.go`'s `TestWebShouldNotImportScoring`, `internal/web/compare_test.go`'s `TestCompareShouldNotImportScoringOrStandings`. Removed each file's now-unused `go/parser`/`go/token`/`path/filepath`/`strconv` imports where nothing else in the file still used them (checked each individually via `grep` before removing).

Verified each new depguard rule actually fires, not just that the config parses, before deleting the tests it replaces: temporarily added a blank `_ "internal/auth"` import to `scoring.go` (a genuinely forbidden internal/ import for that package, using a blank import specifically to avoid an "unused import" compile error masking the depguard check), confirmed `task go:lint` reports `import '...internal/auth' is not allowed from list 'scoring' (depguard)`, restored. Repeated the same proof for the `compare` rule with a blank `_ "internal/standings"` import in `compare.go`, confirmed the exact `desc` reason ("compare.go is display-only over the store") appears in the lint output, restored. Confirmed by the full clean `0 issues` baseline (both before and after each temporary break-and-restore) that `leaderboard.go`'s legitimate `internal/standings` import is never flagged, proving the `compare` rule's file-scoping doesn't over-apply package-wide.

Verified: `gofmt -l` clean, `go vet ./...` clean, `go build ./...` clean, `task go:lint` 0 issues, `task go:test` full pipeline green (95.4% total coverage, unchanged despite 4 fewer test functions - coverage measures `internal/...` line reachability, not test count), `task go:test:acceptance` full pipeline green (84.0% coverage, unchanged), `task go:run` builds and starts. `task docker:build` could not run in this sandbox (docker credential helper fails trying to reach a VS Code Dev Containers IPC socket unavailable here - a pre-existing environment limitation, not caused by this change); `task go:lint` uses the identical pinned `golangci-lint@v2.12.2` the Docker build's lint stage would use, so this doesn't reduce confidence in the config itself.

Nothing incomplete or risky.

**Review patches:** applied five `patch`-routed blind-hunter findings — added two rules the original four (scoring/standings/web/compare, mirroring the deleted hand-tests exactly) left uncovered despite being squarely within AD-8's actual rule: `auth` (allow-list `$gostd`+clock+mailer+store, matching `internal/auth/README.md`'s own stated import contract, which nothing previously enforced) and `infrastructure` (covering `internal/store`/`internal/mailer`/`internal/clock` together, allow-list `$gostd` plus the two third-party modules they actually use, enforcing AD-8's "infrastructure depends on nothing above it" half, which also had zero enforcement before); fixed a real double-diagnostic bug where `web`'s package-wide rule and `compare`'s file-scoped rule both matched `compare.go` and both denied `internal/scoring`, so a single violation there would have fired two separate messages - excluded `compare.go` from `web`'s file list, since `compare`'s own strictly-more-specific rule already covers it; added an explanatory comment block documenting that the `scoring`/`standings`/`auth`/`infrastructure` allow-list rules are deliberately stricter than the hand-written tests they replace (a genuinely new third-party dependency in one of these packages will now also fail `task go:lint`, not just an internal-package violation), including where to widen the list when one is actually needed; and corrected `internal/auth/README.md`'s stale import-contract sentence, discovered while verifying the new `auth` rule against reality - it said "internal/store and internal/mailer only," omitting `internal/clock`, which every non-test file in the package already imports. Two findings dispositioned `low, reject`: no diagnostic-quality gap remains for `scoring`/`standings`/`auth`/`infrastructure` beyond the now-documented allow-list tradeoff - adding redundant `deny` entries purely for nicer messages would require hand-maintaining a list of every other known internal package, reintroducing the exact staleness risk allow-mode avoids; and no permanent "test the linter config itself" harness was added - this session's own established verification convention for every build is direct empirical proof (temporarily break, confirm, restore), which this build already did for all six rules, and a config-testing harness is a materially larger, separate undertaking with no existing precedent in this repo. One finding dispositioned `false`: spec/sprint-status tracking still showing in-progress/open mid-review is expected workflow state.

**Re-verified after patches**: re-ran the full empirical break-and-restore proof for both new rules (`auth` against a blank `_ "internal/scoring"` import - no import cycle, unlike a same test tried against `internal/web` first, which correctly failed to even compile since web genuinely imports auth; `infrastructure` against a blank `_ "internal/store"` import added to `clock.go`) and re-verified the `web`/`compare` fix eliminates the double-diagnostic (one `depguard` line, not two, for a scoring import added to `compare.go`) - all three restored cleanly afterward. `gofmt -l` clean, `go vet ./...` clean, `go build ./...` clean, `task go:lint` 0 issues, `task go:test` full pipeline green (95.4% total coverage, unchanged), `task go:test:acceptance` full pipeline green (84.0% coverage, unchanged), `task go:run` builds and starts.
