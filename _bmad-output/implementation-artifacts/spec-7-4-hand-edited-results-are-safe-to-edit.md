## Intent

**Problem:** Today, any shape mismatch inside `results:`/`award_finalists:` (e.g. `playoffs: FLA` where a list belongs) aborts the whole app at startup, a misspelled/unknown key (`stanley_cup_winer`) is silently dropped with zero signal, and every save re-marshals the *entire* document from typed Go structs — silently discarding comments, flow/block style, key order, and any hand-typed key the structs don't declare, for every hand-maintained section (`players`, `prediction_sets`, `teams`, `nhl_players`, `playoff_matchups`, `results`, `award_finalists`), not just the two most likely to be hand-edited mid-season.

**Approach:** Give `Store` a second, parallel representation of the loaded file — the raw `*yaml.Node` document tree, alongside the existing typed `document` struct. Use it three ways: (1) at load, tolerate a `*yaml.TypeError` confined to `results:`/`award_finalists:`'s own line range instead of aborting, so the app still starts with that one entry treated as unset/zero; (2) at load, walk `results:`/`award_finalists:`'s raw nodes to catch a misspelled/unknown key the typed structs would otherwise silently ignore; (3) at write, splice freshly-encoded `login_codes`/`predictions` nodes into the *original* tree and encode that — every other section round-trips through exactly the same node objects it was parsed into, never re-derived from Go values.

## Boundaries & Constraints

**Always:**
- `results:`/`award_finalists:` leniency (AC1/AC2) is scoped to those two sections only, via line-range confinement — a shape error anywhere else (`players:`, `teams:`, etc.) still aborts startup exactly as today; don't broaden this into a general "the app never fails to parse" policy.
- Unknown-key detection (AC1) only checks the *fixed-shape struct fields* the typed structs would silently drop (`results`'s own top-level fields; `divisionMarks`'s `playoffs`/`division_winner`; `seriesOutcome`'s `winner`/`games`; an award-finalist entry's `slug`/`display_name`) — never re-implements "unknown division/round/award," which the existing map-keyed `ResultProblems` helpers already catch correctly today (a map, unlike a struct, keeps every key it's given).
- Every hand-maintained section round-trips through the *same* `*yaml.Node` objects it was parsed into — the write path never reconstructs their content from `s.doc`'s typed fields. Only `login_codes` and `predictions` (the app's own two owned sections, AD-23) get a freshly-encoded replacement node on each write.
- The full existing test suite (every package) stays green — this changes the store's single write path, shared by every write in the app; this is the highest-blast-radius change in this epic so far.
- One startup summary line reports the total problem count (including zero), after the existing per-problem warnings (AC4).
- **Decided 2026-09-27 (human-confirmed):** add a Gherkin acceptance scenario — a save made through the web UI is checkable by reading the persisted file directly afterward, matching this repo's existing `enter_login_code_steps_test.go` pattern.

**Never:**
- Don't try to preserve exact original indentation width for hand-maintained sections — confirmed empirically (see Design Notes) that `yaml.Node` round-tripping preserves comments, flow/block style, quoting, key order and unknown keys (everything AC3 actually lists), but re-derives block-sequence indentation from the encoder's own settings. AC3's own wording never claims indentation as a preserved property, so this is not a gap against the AC as written.
- Don't detect a hand edit made while the app is running (explicitly out of scope per the epic; the operator runbook's stop-edit-restart rule stands unchanged).
- Don't add a second write mechanism or touch `writeLocked`'s atomic write-and-rename (AD-27) or its login-code cleanup (spec-7-2) — this changes only what bytes get marshaled, not how they reach disk.

## Implementation Notes

`Store` (`internal/store/store.go`) gained a `raw *yaml.Node` field and a `toleratedShapeErrors []string` field. `New` now always builds `raw` alongside `doc`: for an existing file it unmarshals the same bytes a second time into a plain `*yaml.Node`; for the bootstrap path it calls `st.raw.Encode(st.doc)` before the first `writeLocked`. When the typed unmarshal returns a `*yaml.TypeError`, `typeErrorConfinedToLenientSections` walks `raw`'s top-level `results`/`award_finalists` value nodes, computes each one's line span (`node.Line` to the deepest descendant's `Line`, via `maxLine`), and checks every `TypeError.Errors` message's leading `line %d:` (parsed by `parseErrorLine`) falls inside one of those spans; if so, `New` keeps going with `st.doc` partially populated and stashes the raw messages in `toleratedShapeErrors` instead of failing. A message it can't parse, or one outside both spans, still returns the original error unchanged - confirmed empirically that a mismatch inside `players:`/`teams:` etc. keeps failing `New` even when a well-formed `results:` section sits right next to it, and that mixing one tolerated line with one untolerated line in the same `*yaml.TypeError` still fails the whole load (spec-7-4's own boundary: no partial tolerance within one error).

`unknownKeyProblemsLocked` (new) walks `raw`'s `results`/`award_finalists` sub-trees and compares each fixed-shape mapping's key names (results' own top-level keys; a `team_marks.<division>` entry's keys; a `series.<round>.<key>` entry's keys; an award-finalist list entry's keys) against the four hardcoded vocabularies the Code Map lists (`resultsTopLevelKeys`/`divisionMarksKeys`/`seriesOutcomeKeys`/`awardFinalistEntryKeys`), reporting any key not on the list at its full dotted path (e.g. `results.stanley_cup_winer: unknown key`, `award_finalists.hart[0].dispaly_name: unknown key`). It never touches the map-keyed vocabularies (division/round/award names) `teamMarkProblemsLocked`/`seriesProblemsLocked`/`awardProblemsLocked` already validate. Split into `unknownTeamMarksKeys`/`unknownSeriesOutcomeKeys`/`unknownAwardFinalistEntryKeys` helpers to keep `gocyclo`'s complexity gate (over 10) satisfied. `ResultProblems` now prepends `toleratedShapeErrorProblemsLocked()` (formats each stashed message as `"results/award_finalists: " + msg`) and `unknownKeyProblemsLocked()` to its existing per-section checks.

`writeLocked` no longer builds `docToWrite` from `s.doc` and marshals the whole thing. It now encodes only the cleaned `login_codes` slice and `s.doc.Predictions` into two fresh `yaml.Node`s, and splices them into `s.raw`'s top-level mapping via a new `spliceNamedValueLocked(mapping, key, value) (restore func())` helper - which replaces an existing key's value node in place, or *appends* a new `key: value` pair when the key isn't present at all (a hand-seeded fixture, or a pre-spec-7-4 file, that omits `login_codes:`/`predictions:` entirely still has to succeed). It then `enc.Encode(s.raw)` instead of the old typed `docToWrite`. Both splices' restore closures are captured before the encode/write/rename sequence runs; any failure from that point on calls them in reverse order (predictions' splice undone before login_codes') so a failed write leaves `s.raw` exactly as it was - `mapping.Content`'s slice-truncate-on-append-undo has to happen in LIFO order since each closure recomputes `len(mapping.Content)` at call time. `topLevelMapping(n)` handles both node shapes `s.raw` can be in: a `DocumentNode` (from unmarshaling file bytes, `Content[0]` is the real mapping) or a bare `MappingNode` (from `Node.Encode`, which never wraps in a `DocumentNode` - confirmed empirically with a throwaway script before writing this code).

Empirically confirmed (throwaway script) that a splice into `s.raw`'s `Content` slice, followed by `enc.Encode(s.raw)` with `CompactSeqIndent()` still set, produces identical output to the old typed-marshal path for `login_codes`/`predictions` while leaving every other section's node objects (and therefore their comments, flow/block style, quoting, key order, and unknown keys) completely untouched - including a hand-typed `results:`/`award_finalists:` entry New tolerated at load, which a save now leaves byte-for-byte where it was (only a block-style sequence's indentation column can shift, per the frozen Design Notes' documented exception - award_finalists' own per-finalist list is the one hand-maintained sequence this applies to).

`main.go`'s `openStore` now always logs one `slog.Info("result problems found", "count", len(problems))` line after the per-problem `Warn` loop (AC4, count 0 on a clean file too), and its doc comment no longer claims a results-section shape error "still fails to load." `main_test.go`'s two `TestOpenStoreShould...` tests were updated to assert on the new summary line instead of `logs.Len() != 0`.

`docs/recording-results-and-playoffs.md`'s "Reading the startup warnings" section (only that section touched, per the Code Map's explicit line-range scope) now lists the misspelled/unknown-key case and the wrongly-shaped-entry case under "warns about" instead of "not warned about," reworded the remaining not-warned-about bullet to explicitly scope "still stops the app from starting" to *outside* `results:`/`award_finalists:`, and documents the new summary line. Left untouched (out of the Code Map's declared scope, flagged below under Verification): line 73's "a flat `round1.s1:` key doesn't load and stops the app from starting" and the "The app rewrites the whole file" section (lines ~25-34) are both now stale for `results:`/`award_finalists:` specifically - see Verification's "left incomplete" note.

Acceptance test: `src/acceptance-tests/features/hand-edited-results-are-safe-to-edit.feature` + `src/acceptance-tests/hand_edited_results_steps_test.go`, wired into `suite_test.go`. Seeds a data file directly (not via the shared `lazyFixture` helper, so the hand-typed `results:`/`award_finalists:` bytes - comment, flow style, unusual key order - are under exact control, mirroring `enter_login_code_steps_test.go`'s own pattern), submits a real `POST /predict/cup` pick through `web.NewServer` with a signed session cookie, then reads the persisted file directly and asserts the comment/flow-style/unusual-key-order fragments all survive. ## Design Notes

**Empirically confirmed (throwaway script, `go.yaml.in/yaml/v3`):**
- `yaml.Unmarshal` into a typed struct, given a nested type mismatch (`playoffs: FLA` into `[]string`), returns a `*yaml.TypeError` (exported `Errors []string`, one entry per mismatch, each prefixed `line N: `) but still populates every field it *can* — including sibling fields in the very same struct. This is what makes AC2's "still starts" achievable without a hand-rolled tolerant decoder: just don't treat this specific error class as fatal.
- A misspelled/unknown struct field (`stanley_cup_winer`) produces **no error at all** — `err == nil`, the field is simply never populated. This is why AC1 needs a separate raw-node key-name walk; `TypeError` cannot help detect this class.
- Round-tripping a full document through `yaml.Node` (`Unmarshal` into `*yaml.Node`, then `Encoder.Encode` that same node) preserves: comments (both inline and standalone, with a minor comment-padding normalization from 3 spaces to 1), flow-vs-block style choice, quoting, and key order — confirmed with a fixture containing all of these plus an unrecognized key. It does **not** preserve original indentation width for block-style sequences: the encoder's global settings (`CompactSeqIndent`, spec-7-3) still govern how far a `-` sits from its parent, uniformly, for every sequence in the tree, hand-maintained or not. The Go library's own doc comment for `Node` confirms this directly: "the content when re-encoded will not have its original textual representation preserved... an effort is made to render the data pleasantly." This repo's documented hand-editing convention (`docs/recording-results-and-playoffs.md`) already uses flow style (`[FLA, TOR, TBL, BOS]`, `{winner: FLA, games: 5}`) for exactly the collections that would otherwise hit this indentation quirk, except `award_finalists.<award>`'s own per-finalist list, which is block-style and would have its indentation re-derived (its *content*, comments and key order stay exact — only the `-`'s column shifts).
- Confining leniency by line range (rather than excluding `Results`/`AwardFinalists` via `yaml:"-"` and decoding them separately) keeps `document`'s tags untouched and reuses `New`'s existing single-unmarshal-call shape, at the cost of a small string-parse on `TypeError`'s stable, long-documented `line %d:` message format.
