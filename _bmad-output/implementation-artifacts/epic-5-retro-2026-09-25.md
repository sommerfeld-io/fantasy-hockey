## Findings

Findings are grouped by source. Each carries its disposition: **fix now** (→ action item), **defer** (tracked, not urgent), or **accept** (recorded, not re-flagged).

### Aggregate views

**Duplication map:**

1. **`isGatedRound` reimplements two things that already exist** (`src/internal/web/compare.go:217-237`, corroborated independently by the duplication-map analysis, the architecture-delta analysis, and the Adversarial review lens):
   - A "find the Prediction Set matching this id" scan, when `findPredictionSetByID` already does exactly this in `src/internal/web/sheet.go:271-278`. There are now three independent "match a Prediction Set id" implementations in the package (`findCompareSet`, `findPredictionSetByID`, `isGatedRound`'s inline loop).
   - The phase/deadline validity check already written in `selectableCompareSets` (`compare.go:244-253`) in the same file.
   - **Disposition: fix now.** This is exactly the kind of duplication that already caused a real bug once (the medium-severity finding fixed in `3b9bf1b`, where the validity check was dropped and had to be re-added) — the fix went as far as re-adding the check inline, not as far as sharing it, so the same class of drift is still possible.
   - **Process lesson:** when a review-fix patch re-derives logic that already exists as a re-check (not just a symptom-level correction), the fix should reach for the existing helper, not rewrite the check inline a second time.

2. **Acceptance-test "player pool" fixture pattern duplicated from Leaderboard's step file** (`src/acceptance-tests/compare_predictions_steps_test.go` vs. `leaderboard_steps_test.go`): `comparePlayerID`/`leaderboardPlayerID`, `requirePoolPlayer`, `thePoolPlayersAre`, and the `seedBody` player-seeding loop are near-identical or byte-identical pairs, none hoisted into the shared `fixture_support_test.go` that already holds other cross-file acceptance helpers (`writeSeedTeams`, `mustSeedRound`, etc.).
   - **Disposition: fix now** (small-medium remediation: extract a shared player-pool helper).
   - **Process lesson:** this is the fourth epic in a row with an action item to hoist duplicated acceptance-test fixture helpers (epic-2 item 12, epic-3 item 22, epic-4 item 34, now this). The recurring fix isn't landing as a lasting habit — worth turning "check `fixture_support_test.go` and sibling step files before writing a new fixture helper" into an explicit pre-write step (e.g. in `src/CLAUDE.md`'s acceptance-test guidance) rather than a retro cleanup each time.

**God-class / size growth:**

3. **`compare.go` is now the largest production file in `internal/web`** (488 lines, ranked via `git_evidence.py`'s per-path churn, confirmed against real current file size with `wc -l`) — bigger than `sheet_divisions.go` (421) and `sheet_awards.go` (399), the very files this package's own Epic 2 retrospective (`epic-2-retro-item-10`) split *out of* a single `web.go` for this exact reason ("mixes routing plus 4 distinct sheet-kind view-model families... in one file, with no same-package file-splitting used"). `compare.go` now mixes the same four category-kind families (single-team, division, award, series) in one file. Neither `epic-5-context.md` nor spec-5-1's Design Notes justify this beyond "Compare lives in `internal/web`, as Leaderboard does" — which answers *package* placement, not *file-splitting*.
   - **Disposition: defer.** Not urgent (488 vs. the pre-split `web.go`'s 1,698 lines), but tracked so a future Compare-touching story doesn't push it further before a split is considered.
   - **Process lesson:** story/epic planning should check a target file's size against this package's own established split-threshold precedent as a planning-time gate, not only discover it in retro.

**Spec-to-implementation reconciliation:** clean. No divergence found beyond what both stories' own Review Triage Logs already caught and reconciled (verified against epics.md's FR-25–28, `epic-5-context.md`'s Requirements, and both frozen specs).

**Architecture delta:** clean. Import boundaries hold (`compare.go` imports neither `internal/scoring` nor `internal/standings`; `TestCompareShouldNotImportScoringOrStandings` verified to actually catch a *used* forbidden import — an *unused* one is rejected by the Go compiler first, which is the case that matters). Two minor, non-blocking style notes: a `(Boundaries: ...)` comment annotation unique to `compare.go` (not used by any sibling file), and one place where "wrap the error" and "log it" are collapsed into a single statement where `predict.go`/`sheet.go` split them — both **accept as-is**, not worth an action item.

### bmad-review (diff-scope, weighted at the 5.1/5.2 boundary)

**Verification-gap lens:** no findings. Every 5.1/5.2 interaction point checked (the `compareValueView` refactor across all four category builders, `isGatedRound` vs. `selectableCompareSets`/`defaultCompareSet`, the CSS cascade between `.chip`/`.cmp-value` (5.1) and `.cmp-tag`/`.cmp-value--empty` (5.2)) has both unit- and acceptance-level coverage; none of the constructed regression scenarios could be made to pass undetected.

**Adversarial lens (10 findings) + Edge-Case Hunter lens (1 finding, corroborating #4 below) — consolidated:**

4. **Contradictory simultaneous empty-state messages — confirmed live in the running app with real data (see Behavior verification below), not just a theoretical combination.** When a hand-typed `?set=` names a still-gated round (e.g. `r2`) and that round's own phase group has no other selectable set, the page renders *both* the per-group "Nothing to compare yet." note (5.1) *and* the page-level dashed "Matchups not set." note (5.2) at once — two different explanations for the same state, with no test covering the combination (every existing test/scenario for the gated-note path uses a fixture where the Playoffs group still has other selectable chips).
   - **Disposition: fix now** — upgraded from what static analysis alone would suggest ("rare/unreachable edge case") because it reproduces today against the live data file, not a contrived fixture.
   - **Process lesson:** when a later story adds a new "nothing to show" state to a selector/table pattern an earlier story already gave its own empty-state handling, enumerate the *combined* state matrix (both conditions true at once) as an explicit spec I/O row, not just each condition individually.

5. **Test coverage gaps at the story boundary** (three related, smaller items, all **fix now** — cheap, no behavior change):
   - The signed-in player's own column (5.1's `cmp-cell--own`/`cmp-player--own`) is never tested holding a tag-styled value (5.2's `.cmp-tag`) at the same time — every tag/plain/faint scenario has a *different* player make the pick than the one opening Compare.
   - `isGatedRound` is only ever exercised against `r2`; the other two `roundGatedSetIDs` members (conference finals, Stanley Cup Final) are never driven through this code path in any test.
   - `roundGatedSetIDs` (predict.go) and `seriesSetIDs` (compare.go) are two independent id-classification maps with no test asserting they stay in sync — a future round added to one but not the other would compile and pass every existing test while silently misbehaving only for that round.

6. **Minor, accept-as-is:** the acceptance-test feature file marks `r2` `upcoming: true` in its background even though gating is driven solely by `PlayoffMatchups`, which could read as implying a dependency that doesn't exist (low value to fix, since the fixture is still correct, just slightly over-specified); `.cmp-values .cmp-value`'s blanket `margin-right: 6px` also lands on the last value in a multi-value cell (cosmetic-only, never asserted); a code comment noting reliance on Go 1.22+ loop-variable semantics would be nice-to-have, not necessary (Go 1.26 per `go.mod`, verified safe); `.compare-none` (5.1) and `.cmp-note-dashed` (5.2) are two independently-styled "empty state" messages with no shared base class (relevant given finding #4, but not worth a dedicated item beyond fixing #4 itself).

**Adversarial/Edge-Case items already raised and accepted in the stories' own Review Triage Logs are not re-listed here** (e.g. the `isGatedRound`/`selectableCompareSets` duplication was already flagged in spec-5-2 Pass 1 #2 and Pass 2 #8 — folded into finding #1 above rather than repeated as a new item).
