### Architecture delta

- **F1: The persisted series-key format and the playoff round ids live in the presentation layer, which Epic 4 scoring cannot import.**
    - *Where:* `joinSeriesKey`/`splitSeriesKey` and `seriesKeySeparator` are in `src/internal/web/sheet_series.go:16-31`. The ids `round1SetID`/`round2SetID`/`conferenceFinalsSetID`/`stanleyCupFinalSetID` and `roundGatedSetIDs` are in `src/internal/web/predict.go`.
    - *Why it matters:* The `"r1.e1"` format is written into `fantasy-hockey.yml` as `series_key` (seen in the behavior check). The architecture only allows `web -> feature -> store` (`ARCHITECTURE-SPINE.md:35`), and says application logic belongs in feature packages (line 67) and that `internal/predictions` reads the playoff matchups (AD-23, line 193).
    - *Consequence:* Story 4-1 (automatic scoring engine, `internal/scoring`) has to read series picks by round. It would have to re-implement the key format or import `internal/web`, which is a layering violation.
    - *Disposition:* **fix now.** Move the key helpers and round ids into `internal/store` (AD-24/AD-28 give store ownership of shared identifiers) before story 4-1.
    - *Prevention:* The epic context should name the layer that owns any value that gets persisted.
- **F2: Prediction domain logic keeps growing in `internal/web`, and `internal/predictions` still doesn't exist.**
    - *Where:* Series validation (`seriesSubmissionIsComplete`, `handleSeriesSubmit`) and round gating (`effectiveUpcoming`) are in `src/internal/web`. `ls src/internal` shows `auth clock mailer server store web`.
    - *Status:* Pre-existing since Epic 2, and the 3-2 spec's Code Map chose this placement explicitly. Epic 3 added `sheet_series.go` (355 lines) on top of it.
    - *Disposition:* **open question** (see below). Either accept the deviation from AD-23/architecture line 67 and record it, or plan the extraction.
