### Hand-edited results workflow (user focus)

- **R1. The series-result shape the user approved doesn't load.** In the 4-1 planning decision the user chose the architecture's shape, and the preview showed a flat key: `series: round1.s1: {winner, games}`. That matches `ARCHITECTURE-SPINE.md` "Illustrative data-file shape". The build only accepts a nested form, `series: round1: s1: {…}` (`src/internal/store/store.go`, `results.Series map[string]map[string]seriesOutcome`; `src/internal/store/README.md:13-14`).
    - Verified: a probe with the flat form fails in `store.New` with `yaml: unmarshal errors`, so the app refuses to start.
    - The failure is loud, so no score is silently wrong. But an operator following the approved preview or the architecture document can't start the app.
    - Disposition: **fix now**. The user decided to keep the nested form only and correct the docs (A1).
- **R2. The two stories' docs contradict each other on when a result shows up.**
    - `src/internal/standings/README.md:16` (4-2) says "a new pick or a reloaded result shows up on the next call".
    - The store (4-1) reads results only in `store.New`, and `src/internal/store/README.md` says to stop the app, edit and restart.
    - `epics.md` Story 4.2 AC3 and `epic-4-context.md` ("a new result … shows up on the next open or refresh") still promise a live result.
    - This is the same restart-drift pattern as Epic 3 item 24, which is still open.
    - Disposition: **fix now** (doc and spec reconciliation).
- **R3. The items deferred to "story 7-3" aren't covered by story 7-3.** Four entries in `deferred-work.md` (lines ~84-101) are deferred to 7-3:
    - a misspelled key is silently ignored and then dropped on the next save;
    - a wrongly shaped entry aborts startup;
    - every save rewrites the results section, losing comments and unknown keys;
    - `games` gets re-quoted.

    Story 7.3's ACs (`epics.md`, "Story 7.3: Keep Written YAML yamllint-Compliant") cover only yamllint compliance of the app's writes. Disposition: **fix now**. Give these a real home by extending 7.3's ACs or adding a story.
- **R4. Hand edits made while the app runs are overwritten, and there's no operator guidance.**
    - `writeLocked` marshals the document loaded at startup, so any pick or login-code save overwrites results edited on disk while the app runs (adversarial #2, edge-case).
    - The only protection is one sentence in a developer package README (`src/internal/store/README.md`).
    - There's no `docs/` directory, and Epic 3 item 21 (the playoffs runbook) is still open.
    - `src/fantasy-hockey.yml` has no example `results:` or `award_finalists:` section.
    - Disposition: **fix now** (a runbook). Detecting on-disk changes before a write is **deferred**.
- **R5. Only 2 of the 5 result kinds are tested to survive a save.** `TestSavingAPredictionShouldPreserveTheHandRecordedResults` (`src/internal/store/store_test.go:2282`) checks only `StanleyCupWinner` and the Hart finalist count.
    - Both "hand edit + restart" scenarios regenerate the file from the seed (`automatic_scoring_steps_test.go` `scoringRunsBeforeAndAfterACupEdit`, `leaderboard_steps_test.go` `theCupWinnerIsChangedByHandAndTheAppRestarts`).
    - So a marshal regression in `team_marks`, `presidents_trophy` or `series` would wipe them on the first save with no failing test (verification-gap #2).
    - Disposition: **fix now**.
- **R6. Rewrites change the file's shape.** The behavior check saw these on a save (e2e scratch `data.yml`):
    - `games: 5` became `games: "5"`;
    - flow style became block style, including `playoff_matchups`;
    - comments were stripped;
    - quoted team ids were unquoted.

    The reviewers add two more: `playoffs: []` is added when only `division_winner` was recorded (adversarial #15), and a slug-only finalist gains `display_name: ""` (edge-case). The values survive. Disposition: **defer**, together with R3.
- **R7. More hand-entry mistakes are silent.** A half-recorded series, fewer than 3 finalists, duplicate player ids and a finalist in the wrong position don't produce warnings. There's also no "results loaded, N problems" summary line, so a clean restart looks the same as an unchecked one (adversarial #13/#14, edge-case #2). Disposition: **defer**, together with R3.

### Boundary between the stories (scoring → standings → web)

- **B1. No end-to-end test puts division, award or series points on the Leaderboard.** Every leaderboard fixture seeds only `cup`, `presidents` and `playoffcup` (`leaderboard_steps_test.go` `seedBody`, `web/leaderboard_test.go:22-33`, `standings_test.go:17-30`). The Playoff column is only ever fed by `playoffcup`. The rules are pinned up to `scoring.PlayerPoints` (`scoring_test.go:94`, `max_test.go`), and `TestRowsShouldTakeEveryPointValueFromScoring` pins the handoff (verification-gap #1, adversarial #16). Disposition: **fix now** (one scenario).
- **B2. Two maps must name the same four rounds, and nothing checks it.** `scoring.seriesPoints` and `store.resultRounds` both list them. If one is renamed, that round silently scores 0 (adversarial #12). Disposition: **fix now** (one test).
- **B3. Duplicate or oversized prediction rows.** Duplicate cup, award or series rows each score, while a division row counts once (`scoring.go` `predictionPoints` loop vs `divisionRow`). Hand-edited award or division lists aren't capped (adversarial #3-5, edge-case).
    - This is the third review in a row to raise it: 4-1 Build triage #9, the 4-1 code review "Rejected", and now two retro lenses. It was rejected each time because the `predictions` section is app-written and saves upsert.
    - Disposition: **accept**, recorded here so later reviews stop re-flagging it. The maintainer is also a player, so a hand edit to `predictions` is a trust question rather than a code defect.
- **B4. No consistent snapshot per request, and a quadratic player lookup.** `standings.Rows` calls `scoring.PlayerPoints` per player, and each call clones `Players()` and takes many separate read locks (adversarial #6/#7, edge-case). Disposition: **accept**. The pool has 3 players, and a save that races a render affects one refresh at most.
- **B5.** An empty pool renders an empty table, duplicate player ids produce duplicate rows, and the A–Z tie order isn't locale-aware (adversarial #8/#10/#11, edge-case). Disposition: **accept**. Sign-in needs a player, the ids are hand-maintained slugs, and the names are ASCII. Duplicate-id warnings fold into R7.

## Behavior verification

The real binary was built from `src/` and run on a scratch copy of the data file (port 8097, local mailpit). The scratch copy had an added `results:` section, `award_finalists.hart`, one `r1` matchup and one deliberately malformed team (`XXX`).

- **Startup:** exactly one warning, `results.team_marks.metropolitan.playoffs: unknown team "XXX"`, and the app kept listening. Only `XXX` was ignored.
- **Login:** the email-and-code login worked end to end. The code arrived in mailpit, and `POST /login/code` returned 302 with a session cookie.
- **`GET /leaderboard`:** 200, with one row: rank 1, Sebastian, Regular 95, Playoff 0, Total 95. That matches a hand calculation (divisions 50, Presidents' Trophy 20, Cup 20, Hart 5). The badge and Total had the gold classes, "(you)" was absent, and the caption and footer were present.
- **Live update:** `POST /predict/cup` (still open until 2026-10-06) changed the pick, and the next request showed Total 75. That's the expected 20 fewer.
- **What a save rewrites:** see R6. On restart the rewritten file loaded cleanly, gave the same single warning and still showed 75.
- **Not exercised end to end:** series points on the Leaderboard, because no series pick was saved (see B1). The page also wasn't viewed in a browser, so the phone-width layout is unchecked.
- **Checks:** `task go:run` and `task docker:build` passed on `0d1bee9`. `docker:build` needed an empty `DOCKER_CONFIG`, because the credential helper fails in this devcontainer.
