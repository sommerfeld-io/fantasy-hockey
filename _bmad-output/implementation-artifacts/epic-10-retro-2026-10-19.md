## Behavior verification

The changed flows were exercised against the built binary (`go build`, then a script that starts it with a temporary data file, a registered player, and a listener that counts SMTP connections):

| Run                                            | Observed                                                                                                                                                                                                                                                   |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `MAIL_TYPE=pigeon`                             | Exit status 1; log: `invalid MAIL_TYPE "pigeon": allowed values are SMTP and API`; the app never listens                                                                                                                                                   |
| `MAIL_TYPE` unset, `SMTP_HOST`/`SMTP_PORT` set | `POST /login` returns 200; the listener saw 1 SMTP connection; audit line `login_code_requested player_id=basti`; metric `login_events_total{event="login_code_requested"} 1`                                                                              |
| `MAIL_TYPE=API`, `SMTP_*` set, no `GMAIL_*`    | Startup warning `ignoring mail settings of the unselected transport variables="SMTP_HOST, SMTP_PORT"` (names only); `POST /login` returns 200; 0 SMTP connections; send error `GMAIL_CLIENT_ID is not set`; the same audit line and metric as the SMTP run |

Not exercised: a real send to Google. Every test and this check use local fakes or missing credentials, because the code has no URL override by design. Live behavior (the OAuth exchange, the `gmail.send` scope, the sender account) is unverified until the first production send.

Two observations from the runs: in both transports a failed send still records `login_code_requested` and returns 200, and the failure log line carries no player id (Epic 9 action item 68, see below). With `MAIL_TYPE=API` and missing credentials the app starts cleanly and the first login fails silently from the player's side.
