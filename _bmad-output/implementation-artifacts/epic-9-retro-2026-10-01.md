### Behavior verification

The runtime behavior changed, so it was exercised on the final state (`76a01ee`) rather than inferred from tests:

- `go test ./... -count=1` passes in full.
- Built the binary and ran it against a one-player data file. Observed: `/login` 200; an unknown email 200 with no audit line and no counter change; a known email 200 with `INFO audit event=login_code_requested player_id=basti` and `login_code_requested` +1; the failed send logged `ERROR send login code error="mailer: send mail: dial tcp 127.0.0.1:1: connect: connection refused"` without the address; a wrong code 401 with `INFO audit event=login_failed` (no `player_id`) and `login_failed` +1; a logout without a session 302 with no line. All four login series and all seven save series appeared at zero or the right count.
- Dev compose (9.5, run earlier in this session): port 80 `/login` 200 and `/metrics`, `/metrics/`, `/METRICS`, `/%6Detrics`, `/metrics?x=1`, `//metrics` all 404; `:8080/metrics` 200; the app's own request counter rose only for direct 8080 scrapes.
- Example compose (9.6, run earlier): port 80 `/login` 200, `/metrics` 404; `127.0.0.1:8080/metrics` 200 with 8080 bound to loopback; Mailpit published no ports; the app created `fantasy-hockey.yml` in the mounted directory. Run with the local dev image and `user: root`, because this sandbox cannot run non-root containers (even stock alpine as UID 1000).
- Not exercised: the published `latest` image, an arm64 host, and the image's real UID 1000.

### Direct findings (verified against the current code)

- **F1 — Following the operator guide breaks `task lint` (fix now).** `.folderslintrc` allows `docs/examples` but not `docs/examples/data`, the directory the guide and the compose header tell the operator to create. Reproduced: with the directory present, `lint-folders` reports `Directory is not allowed by config` and exits 1; the repo's commit hook runs the same linter. Missed in the 9.6 review because the scratch directory had been removed before linting. Source: `.folderslintrc`, `docs/operator-guide.md`, `docs/examples/docker-compose.yml`.
- **F2 — Internet exposure is now one config change away, and the abuse limits are still open (decision before go-live).** The architecture spine records, under Deferred, that login codes are 6 digits valid for 10 minutes, `ValidateLoginCode` matches across all Players, `POST /login` can flood a Player with emails, and nothing rate-limits either, with "the app is now internet-facing" (`ARCHITECTURE-SPINE.md:473`). Epic 9 delivered the proxy and the example that make that exposure real, plain HTTP with no `Secure` flag by decision, and the example header says "no HTTPS/443 by decision" but not that brute force is unthrottled. Nothing in Epic 9 closed or even re-flagged it for the operator.
- **F3 — A failed code email cannot be tied to a Player (fix soon).** `src/internal/auth/auth.go:59` logs `slog.Error("send login code", "error", err)` with no `player_id`, and `login_code_requested` is audited before the send completes, so the audit stream reads "requested" for codes that were never delivered. Since 9.2 removed the success line, delivery is not logged anywhere. The `player_id` slug is the one identifier AD-33 permits.
- **F4 — `/metrics` is an email-enumeration oracle for anyone who can reach 8080.** `login_code_requested` increments only for a matched email, so a reader of `/metrics` can watch the counter move after submitting an address. Exposure is controlled by placement (AD-32): the proxy 404s it, the example binds 8080 to loopback, but the dev compose still publishes `8080:8080` on all interfaces. Accepted by AD-32; the operator guide does not say this metric reveals matches.
- **F5 — Observability has no operator documentation (fix soon).** Metric names, the scrape target (`127.0.0.1:8080/metrics`), the audit event vocabulary and the anonymous-access caveat live only in `src/internal/observe/README.md`. The example paragraph in `docs/operator-guide.md` does not link the existing checklist row saying a fresh data file has an empty `players:` list (`operator-guide.md:14`), so a first-time operator following it gets a stack where `/login` answers 200 and nobody can log in. The published `latest` image also predates `/metrics`, so the example serves no metrics until the next release.
- **F6 — AD-31 is enforced for `web` and the feature packages, not for `internal/server` or `main.go`.** No depguard rule has a `files:` pattern for them (`.golangci.yml`), so either could import `client_golang` and lint would pass. The `observe` allow-list also names `internal/clock`, which it does not import.
- **F7 — Returned `Prediction` rows share slices with the store.** The `Save*` doc comments say "a copy", but the copy is a struct copy, so `TeamIDs` and `FinalistSlugs` alias the in-memory rows (`store.go`, `SaveDivisionPicks`, `SaveAwardPicks`). Today only `web` reads `Kind` from them, so nothing breaks; a future caller that mutates one would corrupt state without a write.
- **F8 — The mid-loop failure of a series save is still untested.** Carried from the 9.3 review: the store has no failure seam, so the "third write fails, first two rows still counted" case (AD-35, 9.3 matrix row) rests on code reading and the shared `defer` path.
