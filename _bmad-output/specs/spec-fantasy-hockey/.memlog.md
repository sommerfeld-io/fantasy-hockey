- (non-goal) test
- (decision) Why: replaces a manually maintained Excel workbook for a private, season-long NHL prediction pool among 3 named friends (Basti, Sadl, Tobbi) -- the spreadsheet's hand-calculated scoring and lack of deadline/typo enforcement already caused a real, uncorrected scoring error. Source: PRD SS1 Vision.
- (capability) CAP-1 Authentication & Session. Intent: a Player logs in via a one-time 6-digit code emailed on request, and stays authenticated across a sliding-timeout session, with no password and no player switcher. Success: a request to an unregistered or registered email gets an identical response (PRD FR-1); a code valid for 10 minutes or one use logs the player in (FR-2); the session expires after 30 minutes of inactivity, any request resets the countdown (FR-3); logout ends the session immediately (FR-4). Source: PRD SS4.1, FR-1..FR-5.
- (capability) CAP-2 Prediction Sets & Deadlines. Intent: a Player browses all Prediction sets grouped by phase, sees each one's live status, and can edit any subset of an open set's fields independently until its deadline, after which it's permanently read-only. Success: 4 statuses (Open/Submitted/Closed/Upcoming) render correctly per PRD FR-7; a set locks with no grace period at its deadline (FR-8); later Playoff rounds stay locked until their matchups are recorded in fantasy-hockey.yml (FR-10); an empty required pick scores zero without blocking other picks (FR-11). Source: PRD SS4.2, FR-6..FR-12.
- (capability) CAP-3 Before-the-Season Predictions. Intent: a Player enters 4 separate before-season picks -- Cup champion, Presidents' Trophy, Division playoff-team picks, Division winners, and Player awards finalists -- each validated per its own rules. Success: Division playoff-team picks enforce an exact 8-per-conference, 4/4-or-5/3 split with live caps (PRD FR-15); Player awards autocomplete rejects a non-matching NHL Player name rather than silently accepting it (FR-17). Source: PRD SS4.3, FR-13..FR-17.
- (capability) CAP-4 Playoff Predictions. Intent: a Player re-picks the Stanley Cup winner once the Playoff field is set, and predicts each Series' winner and exact game count per unlocked round, labelled by conference. Success: winner and game-count save together as one atomic unit (PRD FR-19); a later round opens only once its real matchups are recorded in fantasy-hockey.yml (FR-20). Source: PRD SS4.4, FR-18..FR-21.
- (capability) CAP-5 Scoring & Leaderboard. Intent: the app computes every player's Regular, Playoff, and Total points live from recorded predictions and results, with no stored/cached score value, and displays a ranked Leaderboard. Success: point values match the scoring table in companion scoring-rules.md (PRD FR-24); players with an equal Total share the same rank, no tiebreaker (FR-23). Source: PRD SS4.6, FR-23..FR-24; Architecture AD-8 (sanctioned standings->scoring import), AD-15.
- (capability) CAP-6 Compare Predictions. Intent: a Player selects any Prediction set and sees every player's picks for it side by side, with Division picks broken out per division and consistent value formatting. Success: an unfilled value renders as a faint em-dash, never blank (PRD FR-28); Division-pick rows are one-per-division with the winner directly beneath (FR-27). Source: PRD SS4.7, FR-25..FR-28.
- (capability) CAP-7 App Shell & Navigation. Intent: a fixed, mobile-first, dark-theme-only shell with a pinned header, pinned bottom navigation (Predict/Leaderboard/Compare), and a single scrolling content region. Success: header and nav never scroll; only content does (PRD FR-30); no light-mode setting exists anywhere (FR-31). Source: PRD SS4.8, FR-29..FR-31.
- (capability) CAP-8 Persistence & Season Data. Intent: every player's picks are saved and visible to everyone under the same rules, shared across devices; the current season's canonical team and NHL Player lists are available wherever needed; a new pool starts each season while prior seasons' data is retained. Success: picks persist and are visible to all players across sessions (PRD FR-32); season rollover follows companion ARCHITECTURE-SPINE.md AD-30 (one file per season, archived, DATA_FILE repointed) (FR-34). Source: PRD SS4.9, FR-32..FR-34; Architecture AD-9, AD-30.
- (constraint) No admin/management UI of any kind, ever. Real-world results, each Prediction set's deadline, and every Playoff round's matchups are entered only by a human directly editing fantasy-hockey.yml, out of band -- no in-app write path exists or may be added for any of these. Source: PRD SS5 Non-Goals, SS4.4 Notes; Architecture AD-23.
- (constraint) No database engine -- a single fantasy-hockey.yml file is the sole datastore, read/written only by internal/store, with exactly one writer process assumed. Source: Architecture AD-9, AD-27, AD-29.
- (constraint) Server-rendered HTML only -- no JS framework, no SPA/API split, no ORM; the only client-side JS is the shared autocomplete widget and Division-pick live-cap disabling, both cosmetic-immediacy only (the server independently re-validates and enforces on submit). Source: Architecture AD-10 (as amended).
- (constraint) Session is a stateless HMAC-signed cookie, HttpOnly + SameSite=Lax, no server-side session store; Secure is added only once TLS lands via a reverse proxy. Source: Architecture AD-11 (as amended).
- (constraint) Every identity a Player picks by name (a Team, an NHL Player) is referenced everywhere -- prediction, autocomplete submission, and the hand-maintained result record -- by the same stable id (team abbreviation or NHL Player slug), never by free-text display name, to prevent the exact name-typo scoring gap this rebuild exists to fix. Source: Architecture AD-17, AD-19 (as amended); PRD SM-C1.
- (constraint) Mobile-first, dark-theme-only UI; other device sizes and a light mode are not v1 targets. Source: PRD FR-31; UX DESIGN.md Brand & Style.
- (non-goal) Deadline reminder emails (PRD FR-22, UJ-4) -- fully specified for a future version but deliberately not built now; no trigger surface exists anywhere in v1. Source: PRD SS6.2, SS4.5; UX EXPERIENCE.md Deferred.
- (non-goal) Any second role beyond the single Player identity -- no admin/commissioner/scorekeeper account, no spectator/read-only account, no approval step. Source: PRD SS5.
- (non-goal) Registration or invite flow -- the fixed 3-player list changes only by a deliberate out-of-band edit to fantasy-hockey.yml, never through the app. Source: PRD SS5.
- (non-goal) Real-time score updates during games, in-app messaging/chat, public/ranked pools beyond this private group, native mobile apps. Source: PRD SS5.
- (non-goal) A season-selector or multi-season browsing UI, or a Hall-of-Fame-style history page -- history is retained on disk (Architecture AD-30) but not exposed in-app until a second season's history exists to show. Source: PRD SS6.2.
- (decision) Success signal: all three Players (Basti, Sadl, Tobbi) use the app through the entire NHL 2026-27 season, from before-the-season predictions through the Stanley Cup Final, without reverting to the old Excel workbook for any part of the pool. Source: PRD SM-1.
- (assumption) The scoring point-value table (companion scoring-rules.md) is the PM's own initial calibration for season 1, not an externally validated rule set -- may be revisited after a season's real results are in. Source: PRD Assumptions Index, SS4.6.
